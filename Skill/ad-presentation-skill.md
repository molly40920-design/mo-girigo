# 通用型廣告呈現方式與整合規範 (Generic Ad Presentation Skill)

## 📌 核心體驗概念
本規範旨在確保維持專案變現能力的同時，**絕對不干擾使用者的核心互動流程（例如：作答過程、填表過程、主要資訊閱讀）**。
廣告必須在使用者「**獲得完結感與成就感（例如：看到測驗結果、表單送出成功後）**」才進行推播，以確保頁轉換率與留存率不受影響。

這套通用架構包含兩種核心機制：「**全螢幕彈出式廣告 (Overlay Popup Ad)**」與「**文內橫幅廣告 (Inline Ad Banner)**」。此概念隨時可套用於任何前端架構 (Vanilla JS, React, Vue, Next.js 等)。

---

## 1. 全螢幕彈出式廣告 (Overlay Ad / Popup Ad)

這是達到高點擊與高曝光量的主要手段。應抽離為一個全域或獨立的公用模組（例如 `scheduleAd` 或是 `showAdPopup`），不要與核心業務邏輯強耦合。

### 觸發時機 (The Triggers)
在使用者進入最終畫面（如：測驗結果頁、抽獎結果頁、完成感謝頁）時，必須埋設以下兩種觸發點：
1. **延遲自動觸發**：當最終畫面渲染完畢後，設定延遲定時器 `setTimeout`（建議延遲 **3 秒**），讓使用者先接收到他們想要的資訊，然後再以淡入的方式彈出廣告。
2. **行動即時觸發**：當使用者在最終畫面上點擊了「**分享**」、「**複製連結**」或「**離開前的主要按鈕**」時，立刻同步觸發廣告，緊緊捕捉使用者剛完成任務且準備切換視窗時的注意力。

### 防呆冷卻機制 (Cooldown System)
為了避免使用者頻繁進出頁面而被這類全螢幕彈窗疲勞轟炸，負責彈出廣告的模組**必須強制實作冷卻機制**：
- 使用 `sessionStorage` （或 `localStorage`）記錄上一次成功跳出彈窗的系統時間戳記 (Timestamp)。
- 每次接到觸發指令時優先檢查：若距離上次跳出時間**低於 N 秒（建議值：10 秒）**，則判定處於冷卻期，主動攔截並放棄該次的彈窗顯示。

---

## 2. 文內橫幅廣告 (Inline Ad Banner)

這是一種靜態且不具侵入性的展示方式，能完美融入頁面的視覺動線，用來補足那些立即關閉彈窗的使用者。

### 插入位置 (Placement)
- **永遠固定於最終畫面的下半部**（通常放置在結果解析的內文結束之後、操作按鈕區如「再玩一次 / 分享連結」的上方）。
- 嚴禁直接穿插在操作區的核心重點（如測驗首頁、題目中）阻斷閱讀體驗。

### 視覺原則
- 維持與該頁面的主視窗寬度一致（或設定 `100% maxWidth`）。
- 建議套用圓角（如 `border-radius: 8px`）與輕微陰影，並可標註「贊助內容」或「相關推薦」，讓它看起來像是原生內容的一部分。

## ✅ 通用審查清單 (AI Agent Checklist)
當身為 AI 開發助理的你，被要求於任何專案中新增流程頁面或整合廣告時，必須核對以下重點：

- [ ] **無干擾原則**：確認核心流程畫面（作答過程中）絕對沒有調用或渲染任何遮蔽視線的廣告。
- [ ] **延遲觸發實作**：確認結果/結束頁面的主程式碼結尾，已加入延遲自動執行的廣告呼叫（如 `setTimeout(() => scheduleAd(), 3000)`）。
- [ ] **按鈕掛鉤實作**：確認最終頁面上諸如「分享結果」、「複製網址」等互動類按鈕，除了執行原生任務外，也確實同步呼叫了該發送廣告的函數。
- [ ] **視覺定位檢視**：確保靜態橫幅廣告（Inline Banner）元件已經正確且明顯地放置在最終畫面的按鈕區段上方。
- [ ] **冷卻邏輯實作**：檢查跳出全螢幕廣告的核心模組中，是否有呼叫 `Storage` 的 API 進行時間差比對。
